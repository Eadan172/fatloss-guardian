# 设计记录：数据自动持久化 + Docker 一键启动 + 运动课程库打卡联动

> 本文记录该批功能的设计与落地取舍。原始版本写于 2026-09-06，其后几次迭代改变了部分实现细节，
> 下面已按**当前代码**校正，凡与原始实现不同处均以「现实现」标注。

## Context

用户反馈三个问题 / 需求：

1. **数据丢失**：`npm run dev` 打开 localhost:5173 后总要重新导入数据。根因是 localStorage 按 origin（协议 + 域名 + 端口）隔离 —— 换端口（dev 5173 vs docker 8080）、`localhost` 与 `127.0.0.1` 混用、换浏览器、清缓存都会「丢」数据。需要一个跨 origin 的文件级自动备份 / 恢复机制，同时坚守项目「零网络」原则。
2. **一键启动**：希望双击 bat 文件即可启动 Docker 平台并打开浏览器，且 docker 模式能读到最新数据。
3. **运动软件联动**：Keep / 薄荷健康均无开放 API，经确认采用「课程库 + 打卡联动」方案 —— 手动录入课程，打卡页自动生成当日课程清单，勾选联动训练完成状态与时长，点击链接跳转 App 课程页。

## 核心设计：统一备份端点 `/api/backup`

- **dev / preview**：vite 中间件支持 GET + PUT，读写项目根目录 `data/backup.json`
- **docker**：nginx 把同一端点 alias 到挂载的 `data/backup.json`，并通过 `dav_methods PUT` 开放写入
  （**现实现**：早期设计里 docker 侧为只读、POST 返回 405 静默失败；现已统一为 PUT 且 docker 下同样可写）
- 前端逻辑完全一致：dev 录入的数据写入文件 → docker 启动即读到同一份最新数据
- **防误覆盖保护**（后续补齐）：与「启动快照」一致的 state 不回写备份文件。
  否则换一个浏览器 / 换一台设备打开时，那个浏览器里陈旧或为空的 localStorage 会立刻覆盖
  `data/backup.json`，抹掉另一处的数据。只有本次会话真正改动过数据才回写。

## 修改文件

### 1. `vite.config.js` — 备份中间件插件

`localBackupPlugin()`：`configureServer` + `configurePreviewServer` 双挂 `/api/backup`：

- GET：文件存在返回内容，不存在 404
- PUT / POST：收集 body，`JSON.parse` 校验通过后写入 `data/backup.json`（自动创建目录）
- 其他方法：405

### 2. `src/lib/autobackup.js`（新建）

- `restoreFromServerBackup()`：GET `/api/backup` → `validateImport` → 返回 state 或 null（失败静默）
- `scheduleServerBackup(state)`：模块级防抖约 800ms，**PUT** `{app, exportedAt, data}`，catch 静默
- `writeServerBackup(state)`：取消防抖立即写入（用于「清空数据」等不能等防抖的场景）

### 3. `src/lib/storage.js` — schema 演进

- `SCHEMA_VERSION`：本批功能阶段为 **2**（新增 `courses`）；**现实现为 3**（再增加运动水平等档案字段）
- `initialState()` 增加 `courses: []`
- `EMPTY_CHECKIN` 增加 `completedCourses: []`、`planType: 'platform'`
- `migrate()` 补齐 `courses`，并把旧版按「星期」安排的课程迁移为该星期最近一次出现的具体日期
- `validateImport` 增加 `courses` 为数组的校验

### 4. `src/App.jsx`

- 启动：`loadState()` 无档案时尝试 `restoreFromServerBackup()` → `validateImport` → setState 并提示
- 持久化 effect 中追加 `scheduleServerBackup(state)`（受上述防误覆盖保护约束）
- 向 PlanView 传 `courses` + `onUpdateCourses`；向 CheckInForm 传 `courses`

### 5. `src/components/CourseLibrary.jsx`（新建）

课程库管理卡片（挂在 PlanView 内）：

- 列表：日期标签、名称、来源徽标（Keep / 薄荷 / 其他）、时长、链接按钮、删除
- 添加表单：名称、来源下拉、**上课日期**、时长（分钟）、链接（可粘贴 Keep 课程页 URL）；
  来源选「其他」时出现手动填写来源名称的输入框
  （**现实现**：早期为「星期」下拉，后改为具体日期，以匹配真实课程安排）
- 课程 id 用 `Date.now()`；`onChange` 回传整个数组

### 6. `src/components/PlanView.jsx`

- 在「训练计划」卡片后挂载 `<CourseLibrary courses onChange />`
- 「锻炼方案」支持「平台生成方案 / 运动软件跟课」二选一；跟课模式直接列出课程库清单
  （今天的课程置顶高亮），当天无课时给出录入引导

### 7. `src/components/CheckInForm.jsx` — 当日课程清单

- 按 **上课日期** 精确匹配当日课程（**现实现**：早期按星期匹配）
- 每行：勾选框 + 名称 + 来源徽标 + 时长 + 「打开」链接（`target=_blank`）
- 勾选联动：写入 `form.completedCourses`；`workoutMinutes` 自动回填为已勾选课程时长之和；
  全部勾选时 `workoutDone=true`，取消任一勾选则置 false（用户仍可手动改）
- 当天无课时，列出课程库中最近的安排，便于确认课程是否录入到了正确日期

### 8. `nginx.conf`

```
location = /api/backup {
  alias /usr/share/nginx/html/data/backup.json;
  default_type application/json;
  add_header Cache-Control "no-store";
  dav_methods PUT;
}
```

### 9. `docker-compose.yml`

挂载**可写**卷：`./data:/usr/share/nginx/html/data`
（**现实现**：早期为 `:ro` 只读，后去掉只读限制以支持 docker 模式下写入备份）

### 10. `启动.bat` / `停止.bat`（新建，项目根目录）

- 启动.bat：`chcp 65001` → `cd /d %~dp0` → `docker info` 失败则启动 Docker Desktop 并轮询等待就绪
  （最多约 90s）→ `docker compose up -d --build` → `start http://localhost:8080` → 暂停显示状态
- 停止.bat：`docker compose down`
- macOS / Linux 对应 `start.sh`

### 11. `.gitignore` / `README.md`

- `.gitignore` 追加 `data/`（个人健康数据绝不入库）与 `.trae/`（本地工具目录）
- README：功能模块补「课程库打卡联动」与「自动备份恢复」；一键启动补「双击 启动.bat」；
  目录结构与隐私说明同步更新

## 验证

1. `npm run dev` → 打卡 / 建档 → 项目根目录生成 `data/backup.json`
2. 控制台清 localStorage → 刷新 → 出现「已从本机备份恢复」且数据完整
3. `docker compose up -d --build` → 打开 :8080 → 自动恢复同一份数据（可读写）
4. 双击 `启动.bat` → Docker Desktop 自动拉起、容器启动、浏览器自动打开
5. 计划页添加一门 Keep 课程（日期设为今天）→ 打卡页出现该课程 → 勾选后 `workoutMinutes`
   自动回填、全勾后 `workoutDone` 自动为 true → 点「打开」跳转课程页
6. 换一个浏览器打开应用，不会覆盖已有的备份文件
7. `npm run build` 通过；确认 `git status` 不包含 `data/`
